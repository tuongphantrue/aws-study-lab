Database service selector

Compare managed AWS database patterns by data model, availability, and scaling behavior.

Application profile

Architecture recommendation

Selection hierarchy

Start with access patterns and consistency needs, then choose the managed service with the lowest operational burden.

  • RDS: familiar engines and relational workloads.
  • Aurora: cloud-native relational performance, replicas, and global options.
  • DynamoDB: serverless key-value/document scale with known access patterns.
  • ElastiCache: cache data; it is usually not the system of record.

High availability trap

RDS Multi-AZ improves availability and failover. Read replicas primarily improve read scaling and can also support some DR designs.
