1 · Start here

The big idea

The strongest clue is how the application reads and writes data: joins and transactions, known keys, caching, graphs, or analytics.

2 · Step by step

What AWS does

  1. Identify the data model and consistency requirement.
  2. Estimate scale, traffic shape, and availability needs.
  3. Choose the managed service that naturally matches the access pattern.
  4. Add replicas, Multi-AZ, or global features only when required.
3 · When to use it

Choose it for these requirements

  • RDS or Aurora for relational SQL
  • DynamoDB for key-value/document access at scale
  • ElastiCache for temporary hot data and sessions
4 · Exam tip

Words that guide the choice

RDS Multi-AZ is mainly for availability. Read replicas are mainly for read scaling.

5 · Common mistake

Do not confuse these ideas

A cache is normally not the durable system of record.

RememberData model first; scale and availability second.
